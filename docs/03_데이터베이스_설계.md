## 4. 관계와 무결성

- 관계별 1:1/1:N/N:M, 소유자, FK, 삭제 전파·거부 정책을 정의한다.
- 상태값과 허용 전이는 05를 참조한다. 문서마다 다른 열거형을 만들지 않는다.
- 중복·동시 수정·재처리 시 유지할 불변 조건을 명시한다.
- 인덱스는 실제 조회·정렬·필터 조건을 근거로 선택한다.
- 관계가 확정된 뒤 ERD와 엔터티 ID를 연결한다.

## 5. 데이터 수명주기와 변경

수집 목적, 최소 수집, 접근 권한, 보관 기간, 삭제/익명화, 백업의 삭제 반영을 기록한다. AI 사용 시 원문·출처·생성 결과·검토 기록을 저장할지 별도 결정한다.

마이그레이션마다 변경 파일, 이전/이후 상태, 기존 데이터 처리, 호환성, 적용·검증·복구 절차를 기록한다. 데이터 복구와 코드 롤백은 별개로 검토한다. 실제 개인정보를 seed에 넣지 않는다.

## 6. 완료 기준과 다음 작업

## 8. 초기 PostgreSQL 구현 (2026-10-16)

- 실제 테이블: media, jobs, claims, evidence, checks, verdicts, usage_reservations. DB-006 교차 모달과 감사 로그는 후속이다. 001_initial.sql은 반복 실행 가능한 초기 DDL이며 운영 스키마 변경 관리/백업은 별도다.

## TASK-023 원문 관측 추적 저장

근거의 sourceTrace를 기존 jobs.result/claims/evidence JSON에 저장한다. 원문 전문/HTML·Brave JSON/스니펫은 추가 저장하지 않는다. sourceTrace는 raw/text 해시·서버 수집 시각·요청/최종 URL·정규화 구조 offset·meta/time 관측값/위치·유보 상태를 담는다. 기존 삭제/24시간 경계와 같이 수명주기를 관리하며 과거 결과에 관측값을 소급 생성하지 않는다. 추가 보관이 실제 계약상 허용되는지는 TASK-016 실연동 전 확인한다.

## 출처 검토 결과 저장 (2026-10-19)

sourceReview를 기존 결과/근거 JSON에 추가했으며 legacy는 null이다. 버전/registryVersion·등록 대조 상태·가능한 관계 그룹/신호를 저장하고 실제 independence는 unverified로 남긴다. sourceTrace에는 최대32개 canonical/cite 관측 URL/locator와 sourceLinksComplete가 추가됐다. 과거 parser v1의 누락 링크는 빈 목록/미완전으로 읽고 소급 관측을 만들지 않는다. SQL 변경 없이 기존 삭제/보관 경계를 따르며 실제 원문/API 응답의 이용/보관 권한은 별도 확인한다.
