근거: [기획서 원문](../references/FactLens_AI_기획서_원문.md) 10~11절. Vue 3 + TypeScript + Vite를 개발용으로 채택했고 apps/web에 단일 워크스페이스와 컴포넌트를 구현했다. 인증 화면은 후속이다.

| ID | 화면 책임 | 연결 |
|---|---|---|
| UI-001 | 서비스 소개·직접 업로드·지원 범위/제한·분석 시작; URL 입력은 확장 단계 | FEAT-001, API-001/002 |
| UI-002 | 전처리·음성·시각·검색·교차검증 진행과 오류/재시도 안내 | FEAT-009, API-003 |
| UI-003 | 종합 요약·플레이어·주장/모달 결과·검증 한계·타임라인·이력 | FEAT-007~009, API-003/004/006/007 |

타임라인 선택은 플레이어/주장/근거 카드와 동일 구간으로 연결한다. MP3/WAV에는 음성 재생과 시간 구간 표시를 제공하고 없는 프레임을 오류로 만들지 않는다. 단일 ‘진실 확률’ 대신 판정·근거 강도·불확실성을 분리해 표시한다. 외부 근거 원문/OCR/모델 출력을 비신뢰 콘텐츠로 렌더링하고 키보드 접근과 화면 낭독을 검토한다. 이 항목들은 최종 설계 요구다. 현재 UI 구현/검증 범위는 §8과 10 §22를 따르며 근거 강도 전용 표시와 OCR/시각 결과는 미완료다.

## 1. 현재 상태

제품 화면·컴포넌트·manifest는 apps/web에 구현했다. 단일 워크스페이스 화면에서 업로드/진행/보고서/이력을 전환한다. OmniRoute 대시보드는 외부 개발 도구이며 제품 프런트엔드가 아니다. 원문은 Vue 3 + TypeScript + Vite를 제안한다. 호환성과 세부 구조는 검증 전이며 제품 파일은 생성하지 않았다.

## 2. 선택할 구조

`TASK-003`에서 화면 상호작용, 렌더링/검색 노출 요구, 접근성, 팀 운영 조건을 기준으로 프레임워크·언어·스타일·데이터 접근 방식을 비교한다. 선정 근거는 01의 `DEC-002`에 연결한다.

## 3. 화면·라우트 목록 양식

| ID | 화면/라우트 | 사용자·권한 | 연결 기능/흐름 | 데이터/API | 주요 상태 | 실제 파일 |
|---|---|---|---|---|---|---|
| UI-NNN (양식) | 확정 후 입력 | 허용/거부 | FEAT-/FLOW- | API- | 로딩/빈 값/오류/성공 | 구현 후 연결 |

각 화면에 입력·검증·제출·중복 제출·오류 복구·완료 피드백을 작성한다.

## 4. 모듈 책임 작성 항목

- 라우트/페이지: 사용자 여정 진입과 화면 조합.
- 기능 영역: 실제 업무 규칙과 화면 동작의 경계.
- 공통 UI: 반복 근거가 확인된 요소와 접근성 계약.
- API 클라이언트: 04 계약, 인증 전달, 오류 변환과 취소/타임아웃.
- 상태: 서버 상태/화면 임시 상태/인증 상태의 소유자와 갱신 조건.
- 타입/검증: 사용자 입력·외부 응답의 경계 검증 책임.

이는 책임 검토 항목이며 위 이름의 폴더를 만들라는 지시가 아니다. 채택한 구조에 실제 경로·의존 방향을 기록한다.

## 5. 검증 기준

기능별 인수 조건에 맞춰 컴포넌트/통합/E2E 중 필요한 수준을 선택한다. 키보드 탐색, 레이블, 오류 안내, 작은 화면, 로딩·빈 값·오류 상태를 확인한다. 임의의 성능 목표나 테스트 통과를 기록하지 않는다.

## 6. 완료 기준과 다음 작업

## 7. 기획서 화면별 표시·상호작용 요구

근거: [원문](../references/FactLens_AI_기획서_원문.md) 08·10.2·11절. 화면/컴포넌트 구현 및 라우트 확정 전이다.

| 화면 | 표시 항목 | 사용자 동작과 데이터 연결 |
|---|---|---|
| UI-001 메인 | 소개·파일 업로드·지원 파일/제한·분석 시작 | API-002→API-001 연결 방식은 계약 후 확정; URL 입력은 확장 범위 안내 |
| UI-002 진행 | 전처리·음성·시각·검색·교차검증 단계 | API-003 상태로 갱신; 진행률 산식/조회 주기는 미정 |
| UI-003 결과 요약 | 주요/확인/반박 주장 수·불일치 구간·종합 판정·검증 한계 | API-003/007; 주요 주장 정의와 집계 분모는 TASK-013에서 결정 |
| UI-003 플레이어/결과 패널 | 재생·시간 이동·자막/발언·선택 주장·모달/근거/이유 | API-004/006; 선택 구간과 카드의 같은 원본 시간축 유지 |
| UI-003 타임라인 | 주장·음성/자막 불일치·화면 출처 문제·추가 확인 구간 | 유형/구간 선택→재생 위치·상세 패널 연결 |
| UI-004 근거 상세 | 원문 주장과 인용/위치·발행 정보·URL·검사·판정 근거 | API-005; 원문/근거를 나란히 비교하고 접근 실패/한계 표시 |

음성 전용 입력에는 음성 재생/시간 탐색을 제공하고 프레임 부재를 실패로 표시하지 않는다. 실제 오류 구간과 단순 검토 필요 구간의 표현을 구분한다. 근거 강도와 판정은 별도 표시하고 0~100% 진실 점수로 바꾸지 않는다.

원문 예시 ‘50%/500%/5%’는 시제품/시연 자료로 사용할 때 가상 예시임을 표시한다. 실제 조회 근거 URL을 가짜 주소나 예시 통계로 대체하여 검증 완료처럼 보여주지 않는다. 분석 이력 요구는 유지하되 이력 목록의 별도 UI ID/라우트·인증 방식은 TASK-002/003에서 정한다.

## 8. 구현 파일과 검증 (2026-10-16)

- apps/web/src/App.vue: 단일 페이지 업로드/이력/보고서 상태와 1.2초 단계 조회, 종료 시 polling 해제. api.ts는 HTTP 오류 코드 유지.
- UploadPanel: 파일·동의·크기 사전 검사. AnalysisProgress: 실제 단계명. AnalysisReport: 원본 재생·주장 시간 이동·판정 개수. EvidencePanel: 인용 문자 렌더링과 안전한 HTTP(S) 링크·검사/한계 표시.
- example.ts는 명시적인 가상 보고서이며 실제 업로드의 fallback으로 사용하지 않는다. 모바일/근거 선택/미디어 seek/XSS/오류/삭제 브라우저 검증은 10을 따른다.
- 디자인은 한국어 밝은 워크스페이스/좌측 이력/업로드와 안내/주장·근거 비교 패널. 외부 폰트 요청 없이 시스템 폰트 사용. 운영 로그인과 OCR/영상 결과는 후속이다.

## 승인된 실제 제공자 연결 후속 (2026-10-16)

예산 초과와 제공자 인증/호출/응답 실패를 한국어로 구분해 표시한다. 예산 차단 화면은 실제 AI 분석이 완료되지 않았음을 명시한다. 예시 보고서는 실제 결과를 대체하지 않는다.
