## 1. 제품 목적과 사용자

**FactLens AI**는 영상의 음성·자막·시각 정보를 독립 분석하고, 원자적 주장을 외부 자료와 대조해 허위 주장 및 맥락 왜곡 가능성을 설명하는 의사결정 지원 웹 서비스다. 사용자에게 영상 구간·주장별 판정·근거 원문/URL·분석 한계를 제공한다. 모든 영상의 절대적 진실 보증이나 딥페이크 탐지 자체가 목표는 아니다.

원문의 대상은 일반 뉴스/SNS 이용자, 대학생·연구자, 팩트체크 종사자, 교육기관이다. MVP 일차 사용자와 검증 주제는 TASK-001에서 좁힌다. 목적이 없는 상태로 돌아가 기존 질문을 반복하지 않는다.

## 2. 범위와 단계

| 구분 | 기획 기준 | 구현 상태 |
|---|---|---|
| 필수 입력 | MP4 및 MP3/WAV 직접 업로드 | 미구현 |
| 초기 평가 대상 | 1~3분 한국어 뉴스형 영상 | 데이터 미확보, 하드 제한값 미정 |
| 핵심 파이프라인 | 추출/STT/OCR → 원자적 주장 → 검색 → 원문 검증 → 교차검증 → 규칙 판정 | 미구현 |
| 웹 MVP | 업로드, 진행 상태, 플레이어, 타임라인, 주장·근거, 보고서, 분석 이력 | 미구현 |
| 확장 | 정책상 허용된 URL/기사/플랫폼 입력, 다국어, 실시간, 일괄 처리, 팀 검토, C2PA 등 | 후속 제안 |

원문 진행 단계는 음성 PoC → 시각 PoC → 통합 검증 PoC → 웹 MVP다. URL 입력을 첫 PoC의 선행 조건으로 만들지 않는다. MP3/WAV 직접 입력은 필수 범위지만 최초 PoC에 함께 넣을지는 TASK-001에서 명시한다.

## 3. 제안 아키텍처와 실제 상태

기획 구조: `사용자 → Vue 웹 UI → Node API → Redis 작업 큐 → Python AI Worker → 검증·규칙 판정 → PostgreSQL/미디어 저장소 → 결과 UI`.

Node는 요청·업로드·작업·접근 제어, Worker는 미디어·AI·검색·검증, PostgreSQL은 분석/주장/근거/판정/감사 정보를 담당하는 제안이다. 구체적인 서비스 경계와 큐 라이브러리는 미정이다. 제안 스택과 대안은 06/07/08에 기록한다.

현재 저장소에는 제품 코드·제품 DB·제품 API·제품 테스트가 없다. README는 docs/ 프로젝트 가이드의 진입점을 제공하며 개발 도구와 문서만 준비되어 있다. 개발용 OmniRoute/Headroom 데이터와 대시보드는 제품 구성으로 집계하지 않는다.

## 4. 연구 목표와 비기능 요구

- H1: 외부 근거 활용이 LLM 단독 판정보다 개선되는가.
- H2: 멀티모달 분석이 텍스트 방식이 놓치는 맥락 왜곡을 탐지하는가.
- H3: 근거 검증이 무효 인용과 잘못된 확정 판정을 줄이는가.

모두 미검증 가설이다. A(텍스트 LLM)/B(A+검색)/C(전체 시스템)를 동일 평가 조건에서 비교한다. 90~120개 영상/구간은 목표이며 실제 확보 수가 아니다. 핵심 주장은 별도 주석한다. 데이터 라벨·분할·지표 분모·K·시간/비용 측정·목표치는 TASK-014에서 실험 전 고정한다. Validator와 멀티모달의 독립 효과를 분리할 절제 실험은 검토 제안이다.

보안·접근성·가용성·처리시간·비용·보관 기간 목표값은 아직 미결정이다. 근거 추적, 불확실성 표시, 잘못된 결과 검토 경로, 민감 업로드의 접근/삭제와 외부 전송 정책을 설계해야 한다.

### 접근 대안

| 대안 | 첫 산출물 | 이점 | 비용/한계 |
|---|---|---|---|
| A. 음성 근거 검증 PoC (추천) | 업로드 미디어의 발화·주장·근거·판정 보고서 | 검색과 원문 검증의 유효성을 먼저 측정 | 화면/자막 맥락 왜곡은 후속 PoC에서 평가 |
| B. 멀티모달 통합 PoC | 음성·OCR·프레임 통합 결과 | 최종 가치를 빠르게 시연 | 오류 원인 분리와 비용 측정이 어려움 |
| C. 웹 화면 선행 | 업로드/보고서 UI 시제품 | 사용자 여정 확인이 빠름 | 근거 품질과 판정 성능을 입증하지 못함 |

### 추천 범위

- 일차 사용자: 수업·연구 자료로 뉴스의 주장을 확인하는 대학생/연구자.
- 첫 주제: 국내 공공 통계의 수치·기간·대상 비교 주장. 통계 원문 접근이 가능한 사례부터 선정한다. 의학/개인 의혹 등 별도 전문 검토가 필요한 주제는 첫 평가 묶음에서 제외하는 제안이다.
- 입력: 1~3분 한국어 MP4 및 MP3/WAV. MP4의 첫 단계는 음성만 검증하고 결과에 이 한계를 표시한다. 최대 바이트·정확한 허용 길이·코덱은 TASK-015에서 확정한다.
- 처리: 파일 검증 → 음성 추출/전사 → 타임스탬프가 있는 원자적 주장 → 검색 → 원문 인용 및 기간/수치/단위/대상 검증 → 버전 관리 규칙에 따른 판정 → 보고서.
- 첫 산출물: 원본 구간, 전사, 주장, 근거 URL/인용/위치/발행일, 검증 결과, 판정 이유, 불확실성, 처리 시간·외부 호출 비용 기록. 저장 형식과 스키마는 TASK-004에서 결정한다.
- 최초 PoC는 로컬 개발 검증용으로 제안한다. 웹 MVP의 계정·이력·플레이어와 OCR/프레임 분석은 후속 단계로 유지한다.

### 첫 PoC 인수 기준 초안

1. MP4/MP3/WAV 각각 유효 입력과 손상·허용 범위 초과 입력의 처리 결과를 확인한다. 잘못된 입력은 외부 AI 호출 전에 거부한다.
2. 결과의 각 주장에서 원본 타임스탬프와 근거 원문 위치를 추적할 수 있다. 의견·예측은 검증 대상 제외 이유를 남긴다.
3. 지지·반박·근거 부족·원문 접근 실패·근거 충돌 사례를 구분한다. 검색 결과 없음이나 접근 실패만으로 반박 판정을 내리지 않는다.
4. 발행 기관 이름이나 Agent 합의만으로 확정하지 않는다. 기간/분모/단위가 어긋난 인용은 검증 실패 또는 불충분으로 남긴다.
5. 모델/프롬프트/규칙 버전, 실행 시간과 확인 가능한 외부 호출 사용량을 기록한다. 가격표가 없으면 비용은 미확인으로 표시한다.
6. 성능 합격 수치는 평가 데이터·정답 라벨·지표 분모와 함께 TASK-014에서 실행 전에 정한다. 예제 몇 개의 성공을 연구 성능으로 보고하지 않는다.

### 남은 결정

- 일차 사용자와 첫 검증 주제: 위 추천안 검토 필요.
- 비용/자원: 월 예산 및 1건당 상한, 동시 작업 수, 실행 시간 제한 미결정. 실측 없이 처리 속도나 비용을 보장하지 않는다.
- 데이터: 사용 권한을 확인한 평가 파일과 원문 근거 확보 필요.
- 제공자: API 인증과 모델/검색 제공자 선택은 TASK-003에서 검토한다.

TASK-001 완료 조건은 추천안 검토와 범위/자원 결정 기록이다. 현재는 착수안 작성 상태이며 완료가 아니다.
