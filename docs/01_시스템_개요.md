## 1. 제품 목적과 사용자

**FactLens AI**는 영상의 음성·자막·시각 정보를 독립 분석하고, 원자적 주장을 외부 자료와 대조해 허위 주장 및 맥락 왜곡 가능성을 설명하는 의사결정 지원 웹 서비스다. 사용자에게 영상 구간·주장별 판정·근거 원문/URL·분석 한계를 제공한다. 모든 영상의 절대적 진실 보증이나 딥페이크 탐지 자체가 목표는 아니다.

원문의 대상은 일반 뉴스/SNS 이용자, 대학생·연구자, 팩트체크 종사자, 교육기관이다. MVP 일차 사용자와 검증 주제는 TASK-001에서 좁힌다. 목적이 없는 상태로 돌아가 기존 질문을 반복하지 않는다.

## 3. 제안 아키텍처와 실제 상태

기획 구조: `사용자 → Vue 웹 UI → Node API → Redis 작업 큐 → Python AI Worker → 검증·규칙 판정 → PostgreSQL/미디어 저장소 → 결과 UI`.

Node는 요청·업로드·작업·접근 제어, Worker는 미디어·AI·검색·검증, PostgreSQL은 분석/주장/근거/판정/감사 정보를 담당하는 제안이다. 현재는 Express API와 Redis ID 큐를 소비하는 Python 프로세스로 나눴고 DB가 작업 상태의 기준이다. 제안 스택과 대안은 06/07/08에 기록한다.

초기 문서 작성 당시 제품 코드·제품 DB·제품 API·제품 테스트가 없었다. 2026-10-16 apps/와 Docker 개발 실행·테스트를 추가했다. 실제 AI 제공자는 미연결이다. README는 프로젝트 가이드와 실제 개발 실행·검증 명령의 진입점이다. 개발용 OmniRoute/Headroom 데이터와 대시보드는 제품 구성으로 집계하지 않는다.

## 4. 연구 목표와 비기능 요구

- H1: 외부 근거 활용이 LLM 단독 판정보다 개선되는가.
- H2: 멀티모달 분석이 텍스트 방식이 놓치는 맥락 왜곡을 탐지하는가.
- H3: 근거 검증이 무효 인용과 잘못된 확정 판정을 줄이는가.

모두 미검증 가설이다. A(텍스트 LLM)/B(A+검색)/C(전체 시스템)를 동일 평가 조건에서 비교한다. 90~120개 영상/구간은 목표이며 실제 확보 수가 아니다. 핵심 주장은 별도 주석한다. 데이터 라벨·분할·지표 분모·K·시간/비용 측정·목표치는 TASK-014에서 실험 전 고정한다. Validator와 멀티모달의 독립 효과를 분리할 절제 실험은 검토 제안이다.

개발용 자원/보관 설정은 §10을 따른다. 운영 보안·접근성·가용성/성능 목표와 실제 유료 비용은 미결정이다. 근거 추적, 불확실성 표시, 잘못된 결과 검토 경로, 민감 업로드의 접근/삭제와 외부 전송 정책을 설계해야 한다.

### 추천 범위

- 일차 사용자: 수업·연구 자료로 뉴스의 주장을 확인하는 대학생/연구자.
- 첫 주제: 국내 공공 통계의 수치·기간·대상 비교 주장. 통계 원문 접근이 가능한 사례부터 선정한다. 의학/개인 의혹 등 별도 전문 검토가 필요한 주제는 첫 평가 묶음에서 제외하는 제안이다.
- 입력: 1~3분 한국어 MP4 및 MP3/WAV. MP4의 첫 단계는 음성만 검증하고 결과에 이 한계를 표시한다. 최대 바이트·정확한 허용 길이·코덱은 TASK-015에서 확정한다.
- 처리: 파일 검증 → 음성 추출/전사 → 타임스탬프가 있는 원자적 주장 → 검색 → 원문 인용 및 기간/수치/단위/대상 검증 → 버전 관리 규칙에 따른 판정 → 보고서.
- 첫 산출물: 원본 구간, 전사, 주장, 근거 URL/인용/위치/발행일, 검증 결과, 판정 이유, 불확실성, 처리 시간·외부 호출 비용 기록. 저장 형식과 스키마는 TASK-004에서 결정한다.
- 최초 PoC는 로컬 개발 검증용으로 제안한다. 웹 MVP의 계정·이력·플레이어와 OCR/프레임 분석은 후속 단계로 유지한다.

### 첫 PoC 인수 기준 초안

1. MP4/MP3/WAV 각각 유효 입력과 손상·허용 범위 초과 입력의 처리 결과를 확인한다. 잘못된 입력은 외부 AI 호출 전에 거부한다.
2. 결과의 각 주장에서 원본 타임스탬프와 근거 원문 위치를 추적할 수 있다. 의견·예측은 검증 대상 제외 이유를 남긴다.
3. 지지·반박·근거 부족·원문 접근 실패·근거 충돌 사례를 구분한다. 검색 결과 없음이나 접근 실패만으로 반박 판정을 내리지 않는다.
4. 발행 기관 이름이나 Agent 합의만으로 확정하지 않는다. 근거의 적합성과 주장에 대한 지지/반박 관계는 구분한다.
   - 기간·대상·통계 정의·분모가 달라 직접 비교할 수 없는 자료는 해당 주장의 확정 근거로 사용하지 않는다.
   - 단위만 다른 경우 같은 통계량으로 환산 가능한지 확인하고 원래 값·단위와 환산 방법을 기록한 뒤 비교한다. 비율과 퍼센트포인트처럼 의미가 다른 수치는 임의 환산하지 않는다.
   - 동일 기간·대상·통계 정의·분모의 검증된 직접 근거가 주장과 다른 값을 제시하면 반박 관계를 검토한다. 예를 들어 원문이 확인된 5%와 주장 50%의 차이는 인용 검증 실패가 아니라 반박 후보다. 최종 판정은 TASK-013의 허용 오차·반올림·충돌 규칙에 따른다.
5. 모델/프롬프트/규칙 버전, 실행 시간과 확인 가능한 외부 호출 사용량을 기록한다. 가격표가 없으면 비용은 미확인으로 표시한다.
6. 성능 합격 수치는 평가 데이터·정답 라벨·지표 분모와 함께 TASK-014에서 실행 전에 정한다. 예제 몇 개의 성공을 연구 성능으로 보고하지 않는다.

상태: **제안 — 검토 대기**. 사용자는 프로젝트 가이드에 따른 제작을 요청했다. 기존 원문과 §7을 유지하며 첫 구현을 아래처럼 구체화한다. 이 절은 첫 구현의 설계 기준이며 최종 멀티모달 MVP의 범위를 줄이지 않는다.

### 목표와 접근 비교

목표는 업로드한 한국어 뉴스형 미디어에서 주장·원본 시간 구간·검증된 인용·판정 이유를 사용자가 확인하는 첫 수직 기능이다. 일차 사용자/주제는 §7의 대학생·연구자/국내 공공 통계 추천안을 가정하며 아직 확정하지 않는다.

1. **음성 검증 + 최소 웹 화면 (추천):** 실제 파일→분석→근거 보고서 경로부터 검증한다. 첫 버전은 화면/자막을 검증하지 않는다는 표시가 필요하다.
2. 멀티모달 전체 동시 제작: 최종 가치를 일찍 보여주지만 인식·검색·판정 오류 분리와 비용 측정 범위가 커진다.
3. 화면 시제품 선행: 화면 검토가 빠르지만 실제 근거 검증을 입증하지 못한다.

### 구성과 데이터 흐름

- Vue 3/TypeScript/Vite 웹, Express/TypeScript API, Python 미디어 Worker를 추천한다. 첫 단계의 Worker는 Redis 목록 큐를 소비하고 작업/결과는 PostgreSQL에 기록하는 안이다. 큐 메시지는 작업 ID만 담고 DB가 작업 상태의 기준이 된다. 중복 전달 시 실행 소유권 확인으로 중복 처리를 방지한다. 재시도는 비용 상한을 공유하며 자동 무제한 재시도는 하지 않는다.
- 웹에서 MP4/MP3/WAV를 전송한다. API는 크기·형식을 확인하고 비공개 저장소에 저장한다. 격리된 미디어 검사에서 실제 형식·길이·디코딩 가능 여부를 검사한 뒤에만 AI 단계로 넘어간다. 미디어 검사 실패는 분석 오류로 표시한다.
- Worker는 FFmpeg→타임스탬프 전사→원자적 주장 추출→후보 근거 검색→원문 검증→규칙 판정을 수행한다. 검색/STT/LLM은 제공자 어댑터로 분리한다. 제공자/모델 선택과 인증은 별도 결정하며 인증 부재를 가짜 분석 성공으로 대체하지 않는다.
- 최초 검증 대상은 명시적인 기간·대상·통계 항목·수치가 있는 주장이다. 인용의 실제 존재와 비교 조건이 확인된 직접 근거만 확정 판정에 사용한다. 수치 비교는 원래 단위와 환산 근거를 보존하고, 반올림 허용 오차를 정의하지 못한 사례는 검토 대상으로 남긴다. 충돌은 검토 필요, 부족은 검증 불충분, 의견/예측은 검증 대상 제외로 구분한다.
- 결과 화면은 플레이어/음성 재생, 시간 구간별 주장, 근거 인용·위치·URL·발행 정보, 판정 이유·한계를 제공한다. 첫 단계의 종합 결과는 주장별 판정 개수와 분석 범위 요약으로 제한하며 미정인 종합 판정 우선순위를 임의 구현하지 않는다.

### 실행·인프라와 제약 제안

- 개발 실행은 Docker Compose를 추천한다. AWS를 제품 실행 대상, Cloudflare를 도메인/DNS·HTTPS 진입 경로, Tailscale을 관리 접속 경로로 설계한다. 실제 AWS 자원·도메인·접속 권한과 연결 방식은 확인 전이다. 관리 화면 링크만으로 배포 완료나 계정 접근을 주장하지 않는다.
- 최초 실행은 로컬 비공개 개발용이다. 운영 인증이 준비되기 전 공개 바인딩/배포는 하지 않는다. API 내부 URL이나 DB/Redis를 Cloudflare로 노출하지 않는다.
- 제안 제한: 파일 100 MiB 이하, 길이 180초 이하, 동시 처리 1건, 작업당 검증 주장 최대 5개, 작업 실행 10분 상한. 이 값들은 품질/성능 보장이 아닌 초기 자원 보호 설정이며 검토 후 환경 설정으로 조정한다.
- 외부 유료 호출은 제공자와 건당/월 예산이 결정된 뒤 활성화한다. 호출 전 예상 최대 사용량으로 예산을 예약하고 실제 사용량을 기록하는 계약이 필요하다. 호출 실패도 사용량 기록 대상이다.
- 원본/파생물/전사/결과는 비공개 보관한다. 개발용 자동 삭제 기본값으로 24시간을 제안하고 수동 삭제를 제공한다. 외부 제공자 보관은 별도로 고지한다. 외부 전송 범위와 동의 확인 후 호출한다.
- 원문 수집은 HTTP(S) 공개 주소에 한정하며 사설/루프백/메타데이터 주소와 리디렉션 우회·과대 다운로드를 차단한다. Tailscale 관리 대상은 검색 수집기에서 접근하지 않는다.

### 검증과 첫 완료 조건

- 실제 MP4/MP3/WAV의 업로드→작업→미디어 검사→분석→조회/삭제 흐름을 확인한다. 손상·용량/길이 초과 입력이 AI 호출 전에 거부되는지 확인한다.
- 고정 테스트 자료로 지지·반박·부족·충돌·의견 제외, 기간/분모 불일치, 인용 부재와 URL 접근 실패를 검증한다. 테스트용 제공자 출력은 실제 AI 실행 결과와 구분한다.
- 처리 실패·중복 전달·시간 초과·삭제 중 작업을 검증한다. 근거 없는 확정 판정과 삭제 후 파생물 재생성을 막는다.
- 실제 제공자 연결 검증은 인증·예산·전송 동의가 준비된 후 별도 기록한다. 연구 성능은 TASK-014 프로토콜 고정 후 평가하며 단순 기능 검증과 구분한다.

검토가 필요한 핵심 선택: 추천 접근/사용자·주제, 입력/시간 제한, 예산, 제공자, 보관 기간. 세부 판정·데이터/API·보호 계약과 구현 파일/테스트 순서는 이 설계를 바탕으로 TASK-002/003/004/013/015 및 구현 계획에서 연결한다.
