# 보안·디버깅 병행 점검 (2026-10-20)

대상은 FactLens `P-GISE/Fact-checking-website`의 API 인증/관리자·업로드/삭제·오류 경계다. 기존 작업/회원 데이터에 대한 공격 요청이나 운영 부하 테스트는 하지 않는다. CodeGraph·수동 추적·격리 회귀, 독립 에이전트, Iron Laws와 의존성 감사를 함께 사용한다.

## 재현된 문제와 수정

1. **인증 동시 실행 제한 조기 해제(P2):** 응답 close 이벤트에서 슬롯을 반환해, 연결은 닫혔으나 scrypt/DB 작업은 남은 요청이 전역4개 제한에서 제외됐다. 독립 검토의 실제 비동기 해시 재현에서 미완료 작업8개/거부0을 관측했다. 실제 비동기 인증 핸들러 종료 시 finally에서 슬롯을 반환하는 수정과 중단 HTTP 회귀를 진행한다. register/login/계정 수정/탈퇴의 제한된 경로를 모두 다룬다. 운영 서비스 장애를 재현한 결과는 아니다.
2. **입력 오류 분류:** 잘못된 파일 필드·추가 텍스트·다중 파일이500으로 응답하고, JSON 구문 오류/32KiB 초과가 INTERNAL_ERROR로 분류됐다. 수정 전 새 테스트6개 중5개가 기대 응답과 달라 실패했다. 공통 오류 처리에서 Multer 오류는400 INVALID_UPLOAD, JSON 파싱은400 INVALID_INPUT, JSON/파일 크기 초과는413 SIZE_LIMIT로 분류했다. 수정 후6개 통과. 원문·파일명·비밀번호를 오류 응답에 넣지 않는 회귀도 포함한다.

오류 분류는 [Multer 공식 오류 처리](https://expressjs.com/en/resources/middleware/multer/)와 [body-parser 공식 오류 유형](https://expressjs.com/en/resources/middleware/body-parser/) 및 현재 설치 코드에 근거한다. HTTP/JSON 구조와 기존 파일 제한·인증/소유권 검사는 유지한다.

## 점검 범위와 한계

- 기존 auth.test.ts는 다른 회원의 업로드 참조/작업·주장·타임라인·보고서·근거·미디어 GET와 DELETE404, 소유자 유지/삭제를 격리 DB로 검증한다. 전체 CI에서 재검증하며 공개 DELETE 공격 성공으로 표시하지 않는다.
- `npm audit --omit=dev --json`은 exit0/보고된 취약점0. 알려진 운영 의존성 공지만 확인한 것으로 전체 보안 보증이 아니다.
- Iron Laws MCP의 apps/api/src 점검은12파일/24지적/passed:false. 경로 지적은 storage.ts의 UUID 검증·고정 파일명·O_NOFOLLOW/descriptor 경계와 기존 회귀를 함께 검토했다. auth-config의 URL 파싱 실패 true 반환은 잘못된 공개 설정을 거부하는 동작이다. 정적 지적을 모두 해결/오탐으로 일괄 처리하지 않는다. 검사 범위를 src로 한정해 테스트가 없다는 지적도 실제 tests 디렉터리와 구분한다.
- Strix 코드 보안 스킬의 범위/증거 중심 절차를 적용했다. 별도 모델/스캔 비용이 구성되지 않아 Strix 자동 침투 엔진·managed cloud는 실행하지 않았다. 기존 AI 분석 예산을 스캔 비용으로 사용하지 않았다.
- Windows Docker 엔진은 연결 불가다. 로컬 새 입력 회귀·타입/빌드를 수행했고, 실제 DB/Redis 전체 API·Worker 회귀와 배포 확인은 GitHub Actions에서 실행한다. 아래 배포 결과가 기록되기 전 운영 수정 완료로 취급하지 않는다.

## 후속

### 배포 전 검증 완료

인증 수정의 실제 HTTP 회귀는 수정 전13개 중4실패/9통과, 수정 후13개 통과다. 회원가입/로그인/계정 수정/탈퇴에서 실제 핸들러를 DB 지연 장벽에 둔 뒤 소켓을 끊고 다섯 번째 요청429 유지·실제 작업 종료 후 슬롯 재사용을 확인했다. 동기 입력 예외/비동기 DB 예외/조기 반환과20회 제한도 확인했다. DB만 모의하며 실제 HTTP/Express/scrypt가 실행된다. 성공적인 DB 트랜잭션은 전체 CI에서 따로 검증한다.

독립 리뷰에서 새 회귀19개(인증13/입력6)·API 타입 검사 통과, P1/P2 추가 지적 없음/APPROVE를 확인했다. 부모는 최종 소스 빌드와 diff 검사를 통과했다. 공개 사이트 수정 전 JSON 오류는 실제400/INTERNAL_ERROR로 재확인했다. 다음 게시 커밋의 전체 CI/운영 배포를 확인하기 전 배포 완료로 기록하지 않는다.

인증 중단 회귀/수정 검증→독립 코드 리뷰→전체 CI→자동 AWS 배포·원격 SHA/백업/health 확인 순서다. 운영 격리 복원·고정 IP·원격 백업/보관·경보 정책, 추가 부하/경합·실AI·연구 검증은 별도 후속이다.
