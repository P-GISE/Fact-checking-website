## 3. 기능 상세 양식

기능마다 다음 항목을 채운다.

1. 목적과 사용 시나리오: 행위자, 시작 조건, 완료 결과.
2. 입력·출력: 필수/선택 값, 형식, 길이, 경계값, 표시 규칙.
3. 권한: 누가 어떤 자원에 어떤 동작을 할 수 있는지.
4. 업무 규칙: 상태 변경 조건, 불변 조건, 중복 요청·동시 변경 처리.
5. 실패 처리: 유효성 오류, 권한 거부, 데이터 없음, 외부 장애, 재시도.
6. 저장 및 연동: `DB-`, `API-`, `UI-`, `BE-` ID 연결 또는 해당 없음 사유.
7. 인수 조건: 전제(Given)·행동(When)·관찰 가능한 결과(Then).
8. 검증: 정상/오류/권한/경계 사례와 테스트 경로, 실행 결과.

아직 채택하지 않은 기능을 예시만 보고 자동으로 구현하지 않는다.

## TASK-023 등록 대조·출처 관계 검토 (2026-10-19)

등록 대조는 검토일/근거가 있는 repository 정책의 exact HTTPS 호스트와 페이지에서 관측한 발행자 이름을 비교한다. 이름만 같은 유사 도메인/임의 하위도메인은 미등록, HTTP는 안전한 출처 대조 불가, 이름 불일치/발행자 미확인은 각각 별도 상태다. 실제 등록 정책은 비어 있으며 테스트의 .example 사례는 직접 작성한 가상 입력이다. 등록 표기의 일치는 원문 신원/사실성/최초 게시/독립성 인증이 아니다.

정적 HTML의 link rel=canonical·q/blockquote cite·a rel=cite만 명시 관계 후보로 관측한다. 일반 navigation 링크는 관계 근거로 쓰지 않는다. 링크32개/URL2000자, 비HTTP·userinfo(빈 값 포함)·사설 literal·허용 밖 포트(0 포함)는 거부하고 HTML base 존재 시 상대 링크는 미해석으로 남긴다. 관측 링크를 새로 fetch하지 않는다.

최대5개 후보의 같은 최종 URL·원문/raw 해시·명시 인용 대상/공통 인용 대상·같은 등록 발행자에서 가능한 의존 그룹을 계산한다. 관계는 전이적으로 연결될 수 있으며 페이지의 거짓 인용 표기도 포함할 수 있어 재인용 확인으로 표시하지 않는다. 같은 host만으로 그룹을 만들지 않고 그룹이 없더라도 independence는 unverified다. sourceReview는 판정을 승격하지 않으며 v3의 SOURCE_AUTHENTICITY_UNVERIFIED를 유지한다. 일반 문장/표 의미·실제 신원/출처 계보 검증은 후속이다.

## TASK-023 표 구조 연결 (2026-10-19)

## TASK-023 표 설명 후보 연결 (2026-10-19)
