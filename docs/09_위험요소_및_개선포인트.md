관리자 조회 API는 별도 Secret을 서버에서 검증하며, 화면 경로만으로 권한을 부여하지 않는다. 알려진 오류 코드만 노출하고 원시 예외·본문·토큰을 제외한다. 독립 읽기 전용 리뷰는 인증·Origin·데이터 최소화·비용 계산·로그아웃 이후 응답을 점검했고 재현 가능한 결함을 추가로 찾지 못했다. 이는 전면적인 보안 인증이 아니다.

- main.ts IL-515 HIGH: URL pathname은 컴포넌트 선택에만 사용한다. 실제 관리자 API는 토큰 미설정503/인증 실패401/비허용 Origin403을 서버에서 검증했고 직접 API 회귀로 확인했다. 화면 경로를 접근 권한으로 신뢰하는 구현은 아니다. 정적 원문 지적은 보존한다.
- admin.ts ARC-202 MEDIUM: 조회 핸들러의 DB 직접 접근. 기존 Express 구조에 맞춘 단일 조회이며 SQL은 상수이고 요청 값을 삽입하지 않는다. 계층 분리는 후속 품질 개선이다.
- admin.ts AI-120 LOW: 오류 미들웨어 부재 지적. Router는 app.ts의 공통 4인자 오류 처리기에 연결되며 Express5의 async 예외 전파를 사용한다. 별도 관리자 오류는 같은 error/code/requestId 형식으로 반환한다.
- non-null 단언 지적은 조건식의 타입 축소로 제거한 뒤 테스트/타입 검사와 정적 검사를 다시 실행했다. 기존 고/중위험 전체를 해결한 것으로 처리하지 않는다. Vue 화면의 수동 리뷰·브라우저 검증과 정적 분석의 언어/규칙 범위를 구분한다.

관리자 토큰 방식은 로컬 읽기 전용 관리용이다. 사용자별 계정/소유권·역할 분리·감사로그·접근 제한·백업/복구·공개 TLS 운영은 미완료이며 사이트 전체 보안이 완료됐다고 표시하지 않는다.
