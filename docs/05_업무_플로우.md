## 4. 검토할 경로

- 정상: 시작부터 결과 확인까지 누락된 단계가 없는가.
- 입력/권한 오류: 실행 전 거부할 때 사용자에게 무엇이 보이는가.
- 대기/실패: 외부 연동, 장시간 처리, 취소, 시간 초과를 어떻게 구분하는가.
- 재시도/중복: 같은 동작을 반복할 때 데이터와 비용이 중복되지 않는가.
- 동시 변경: 두 행위자가 변경할 때 충돌을 어떻게 알리고 복구하는가.
- 사람 검토: 자동 처리를 채택한다면 누가 언제 검토·수정·철회하는가.

필요 없는 경로는 해당 없음 사유를 남긴다. 근거 없는 상태나 큐를 먼저 도입하지 않는다.

### 원문 가상 시나리오의 흐름 검토

1. 음성 ‘50%’와 자막 ‘500%’를 각각 원문 구간에 연결한다.
2. 같은 기간/지역/항목의 ‘5%’ 가상 근거를 원문 위치까지 검증한다.
3. 음성↔자막 내부 불일치와 두 주장↔근거의 외부 반박을 별개로 기록한다.
4. 화면이 타지역 과거 영상이라는 직접 자료와 제시 맥락을 확인한 경우에만 맥락 왜곡 판단에 사용한다. 유사 이미지 발견만으로 확정하지 않는다.
5. 반박과 맥락 왜곡의 동시 표시 요구는 보존하되, 종합 우선순위/표현 계약은 TASK-013에서 정한다. 이 사례는 실제 성능 증거가 아니다.

## 8. 초기 실행 상태 (2026-10-16)

- queued → validating → transcribing → extracting → retrieving → validating_evidence → completed. 진행 중 failed 전이 가능. deleted tombstone은 늦은 완료를 거부한다. cancelled는 예약 상태이며 별도 취소 API는 없다. 삭제가 실행 중 작업의 공개 접근/결과 저장을 막는다.
- 실제 제공자 미설정 경로: 업로드 → validating(컨테이너/디코딩) → transcribing(외부 호출 전) → failed/PROVIDER_NOT_CONFIGURED. 가짜 완료 결과를 생성하지 않는다.
- 큐 ID 전달 실패는 DB queued 스캔으로 복구. 중복 메시지는 재실행하지 않고 단일 동시 실행을 유지한다. 원래 started_at 기준 10분 초과는 실패이며 자동 유료 재시도는 없다.

## TASK-023 일반 원문 처리 분기 (2026-10-18)

검색 후보 → 안전한 공개 원문 요청 → 형식/전체 수집 여부 확인 → 원문 구조·발행정보의 근거 위치 연결 → LLM 후보 제안 → 서버 인용/전체 맥락/속성 검증 → 지지/반박/불충분 → 주장 판정 순서다. [02의 계약](02_기능_설계.md#task-023-일반-원문-계약-1차-고정-2026-10-18)을 따른다. 접근 차단/미지원 형식은 다른 후보로 진행하되 거짓으로 간주하지 않는다. 유료 제공자 인증/한도/예산 오류는 기존처럼 실패를 드러낸다.

현재 일반 문서는 v2 전체 맥락 gate에서 주로 유보된다. 이 흐름의 provenance/문서 구조 구현은 후속이며, 구간 인용만 남겨 정정/각주를 제거하는 경로를 만들지 않는다. TASK-023 1차 회귀는 안전한 유보만 검증했다.

## TASK-023 추적 결과의 유보 분기

새로 수집한 원문은 서버 sourceTrace를 갖는다. 같은 인용이 여러 곳이면 QUOTE_AMBIGUOUS, 원문/해시/최종 URL 불일치는 SOURCE_TRACE_MISMATCH, 구조/추출이 일부면 SOURCE_STRUCTURE_INCOMPLETE/SOURCE_EXTRACTION_TRUNCATED, 발행정보 충돌은 PUBLICATION_METADATA_CONFLICT를 기록한다. 페이지 metadata는 자체 표기이므로 SOURCE_AUTHENTICITY_UNVERIFIED가 남아 확정하지 않는다. 레거시 합성 fixture의 메타데이터 입력과 실제 원문 신원 검증을 구분한다. 실제 미디어/외부 검색 흐름은 여전히 TASK-016 조건 확인 후 검증한다.

## 출처 검토와 판정 분리 (2026-10-19)

안전한 원문 수집→canonical/cite 관측→기존 Validator→검토 등록 목록 대조/후보 관계 계산→기존 Decision→저장/화면 순서다. 후보 관계는 현재 주장에 연결된 최대5개 안에서만 계산한다. 미등록/상충/링크 추적 일부/관계 미발견을 독립성 또는 사실성으로 변환하지 않는다. sourceReview는 별도 설명 정보이며 기존 usable/relation/verdict를 수정하지 않는다. 실제 수집 원문의 인증 미확인 유보를 유지한다.


## TASK-023 표 인용 맥락 유보 보완 (2026-10-19)

현재 규칙은 `audio-numeric-canonical-v4`다. 인용 범위가 table_cell/table_header와 겹치면 `TABLE_CONTEXT_UNVERIFIED`를 기록한다. 셀/헤더의 숫자만으로 행·열·분모·단위·주석의 의미를 확정하지 않는다. 관계없는 표가 있다는 이유만으로 문단 인용에 이 사유를 붙이지 않는다. 기존 전체 원문 맥락/출처 인증 유보는 유지하며 일반 표 의미 해석·실자료 정확도 검증은 미완료다. 신규 API 필드/DB 변경 없이 기존 reasons로 전달한다.


## TASK-027 읽기 전용 관리자 화면 (2026-10-19)

운영 관리 링크 → `/admin` → password 필드에 토큰 입력 → Authorization 헤더로 조회 → 상태·오류·월 비용 확인 → 새로 조회 또는 연결 종료 순서다. 토큰은 URL/localStorage/sessionStorage/cookie에 저장하지 않는다. 인증·요청 실패는 원시 서버 오류 없이 안내하고 이전 결과를 지운다. AbortController와 generation으로 연결 종료 뒤 늦은 응답이 관리자 데이터를 다시 표시하지 못하게 한다.


## TASK-023 표 구조 연결 (2026-10-19)

수집한 원문을 static-text-v3로 파싱 → 한정된 단일 DOM 순회에서 표/행/셀 순서와 병합 표기 관측 → 서버 sourceTrace를 Validator/API에 보존 → 유일한 인용의 quoteBlockIndexes에 연결된 위치를 화면에 표시한다. 구조 정보가 늘어도 TABLE_CONTEXT_UNVERIFIED/출처 진위 미확인/전체 맥락 유보를 제거하지 않는다.


## TASK-023 표 설명 후보 연결 (2026-10-19)

원문/인용 검증 → 기존 tableContext 제거 → 유일 인용의 표 선택 → 같은 표의 지원 설명 블록을 원문 순서로 최대16개 추출 → 절단/누락 상태 기록 → API/근거 화면에 표시 순서다. 기존 맥락을 재사용해 다른 인용에 연결하지 않는다. 잘못된 해시/위치·중복 인용에서는 후보를 선택하지 않는다. 이 검토는 판정을 승격하지 않는다.


## 계정·시각 관측 통합 흐름 (2026-10-19)

공개 사용자 흐름은 세션 확인→가입/로그인→서버 소유권 확인→저장량 예약→업로드→외부 전송 동의→분석 생성→음성/내장 자막/표본 프레임/OCR→주장/외부 근거 규칙→별도 모달 비교→주장 집계 보고서→소유자 삭제다. 로그인 실패 시 업로드/이력을 표시하지 않고 로그아웃 시 클라이언트 분석/이력을 비운다.

다른 계정의 미디어로 분석을 생성할 수 없다. 삭제는 소유자를 확인한 후 tombstone/버전 갱신과 파생물을 포함한 폴더 제거를 수행한다. 내부 시각 불일치가 사실 반박이나 외부 근거 확보로 승격되지 않는다. 운영 복구는 일시 미디어/보고서를 되살리지 않고 세션을 전부 폐기한다.
