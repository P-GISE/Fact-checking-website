## 기획서 기반 사용자 흐름 초안

근거: [기획서 원문](../references/FactLens_AI_기획서_원문.md) 4~7·13절. 개발용 화면과 작업 상태 enum은 §8에 구현 상태를 기록했다. 원문 전체 멀티모달 흐름과 운영 권한 계약은 미완료다.

| ID | 흐름 | 연결 | 남은 조건 |
|---|---|---|---|
| FLOW-001 | MP4 업로드 → 요청 생성 → 전처리/STT·프레임·OCR → 주장 추출 → 근거 검색/검증 → 교차검증/독립 검토 → 규칙 판정 → 타임라인·보고서 | FEAT-001~009, API-001~007 | 파일 검증·단계 실패·재시도·부분 결과·완료 조건 |
| FLOW-002 | MP3/WAV 입력 → 음성 경로 → 근거 검증/판정 → 시간대별 음성 결과 | FEAT-001~005/008/009 | 시각 분석은 해당 없음으로 구분; 검증 실패로 표시하지 않음 |
| FLOW-003 | 소유/권한 확인 → 분석 삭제 요청 → 실행 중 처리와 파생물 정리 → 삭제 결과 | FEAT-010, API-008 | 취소/삭제 순서·보관/감사·복구/멱등성 정책 |

내부 모달의 일치가 외부 사실성을 보장하지 않는다. 근거 접근 실패·원문 미확인·검색 결과 없음은 근거 부족 또는 처리 제한으로 기록한다. 신뢰할 근거 충돌은 검토 대상으로 남긴다. 처리 단계 완료와 주장 판정 성공은 별개다. 한 근거/모달 장애 시 전체 실패인지 부분 보고서인지 TASK-013/015에서 결정한다.

원문 사례의 ‘50% 발언/500% 자막/5% 근거·과거 타지역 영상’은 **가상 시나리오**다. 실제 공식 통계나 성능 검증 사례로 표시하지 않는다.

## 1. 현재 확정 범위

사용자 기획서의 직접 업로드→분석→근거/타임라인/보고서 확인 여정을 아래 초안으로 반영했다. 권한·실행 상태·재처리·삭제 동작의 상세 조건은 TASK-002/004/015에서 정의한다.

상태 이름은 실제 설계 시 정하고 02/03/04/06/07에서 동일하게 사용한다.

## 4. 검토할 경로

- 정상: 시작부터 결과 확인까지 누락된 단계가 없는가.
- 입력/권한 오류: 실행 전 거부할 때 사용자에게 무엇이 보이는가.
- 대기/실패: 외부 연동, 장시간 처리, 취소, 시간 초과를 어떻게 구분하는가.
- 재시도/중복: 같은 동작을 반복할 때 데이터와 비용이 중복되지 않는가.
- 동시 변경: 두 행위자가 변경할 때 충돌을 어떻게 알리고 복구하는가.
- 사람 검토: 자동 처리를 채택한다면 누가 언제 검토·수정·철회하는가.

필요 없는 경로는 해당 없음 사유를 남긴다. 근거 없는 상태나 큐를 먼저 도입하지 않는다.

## 5. 개발 작업 흐름

다음은 제품 업무가 아니라 이 저장소의 개발 흐름이다.

`99에서 작업 선택 → 01/02로 목적 확인 → 05로 흐름 설계 → 03/04로 계약 정리 → 06/07 구현 계획 → 구현·검증 → 08/09 영향 확인 → 10/99 갱신`

### 원문 가상 시나리오의 흐름 검토

1. 음성 ‘50%’와 자막 ‘500%’를 각각 원문 구간에 연결한다.
2. 같은 기간/지역/항목의 ‘5%’ 가상 근거를 원문 위치까지 검증한다.
3. 음성↔자막 내부 불일치와 두 주장↔근거의 외부 반박을 별개로 기록한다.
4. 화면이 타지역 과거 영상이라는 직접 자료와 제시 맥락을 확인한 경우에만 맥락 왜곡 판단에 사용한다. 유사 이미지 발견만으로 확정하지 않는다.
5. 반박과 맥락 왜곡의 동시 표시 요구는 보존하되, 종합 우선순위/표현 계약은 TASK-013에서 정한다. 이 사례는 실제 성능 증거가 아니다.

## 8. 초기 실행 상태 (2026-10-16)

- queued → validating → transcribing → extracting → retrieving → validating_evidence → completed. 진행 중 failed 전이 가능. deleted tombstone은 늦은 완료를 거부한다. cancelled는 예약 상태이며 별도 취소 API는 없다. 삭제가 실행 중 작업의 공개 접근/결과 저장을 막는다.
- 실제 제공자 미설정 경로: 업로드 → validating(컨테이너/디코딩) → transcribing(외부 호출 전) → failed/PROVIDER_NOT_CONFIGURED. 가짜 완료 결과를 생성하지 않는다.
- 큐 ID 전달 실패는 DB queued 스캔으로 복구. 중복 메시지는 재실행하지 않고 단일 동시 실행을 유지한다. 원래 started_at 기준 10분 초과는 실패이며 자동 유료 재시도는 없다.
