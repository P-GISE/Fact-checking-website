## 8. 제공자 공통 비용 경계 (2026-10-16, TASK-016)

- metered.py의 BudgetedCall.run(stage, max_cost_micros, operation)은 DB 예약 성공 후에만 operation을 한 번 실행한다. ChargedResult(value, actual_micros)의 확정 사용량만 정산하며 None/예외는 예약을 유지한다.
- 실제 사용량이 상한을 넘으면 알려진 초과액을 기록하고 해당 인스턴스의 후속 호출을 막는다. 이 검사는 이미 청구된 비용을 되돌리거나 제공자의 최대 청구를 보장하지 않는다. 실제 SDK의 모델/출력 제한과 가격 기반 상한 산정이 별도로 필요하다.
- BudgetedProviders는 선택된 제공자의 transcribe/extract/search 반환을 비용 경계로 감싼다. pipeline.py는 해당 usage를 결과에 전달한다. 기본 mode는 disabled이며 openai_brave 프로필의 SDK/예산 조합은 구현돼 있다. 실키/정책/실자료 검증은 남아 있다.
- 호출별 상한·월/건 한도와 실제 비용은 동일한 명시적 통화의 마이크로 단위로 설정해야 한다. 현재 승인 프로필은 USD 공개 단가와 월$20·건당$0.20 상한을 사용하며 실제 청구서는 미검증이다.

- 월 예산은 UTC 당월 비용, 건당 예산은 해당 작업의 전체 예약/확정 비용 합계로 비교한다. 월 경계에서 건당 상한이 초기화되지 않는다. 정산 DB 저장 실패 전에도 메모리의 실제 비용/초과 차단은 갱신한다.

## 승인된 실제 제공자 연결 후속 (2026-10-16)

live_providers.py에 승인 프로필·환경 설정·OpenAI SDK(자동 재시도 0)·Brave HTTP 어댑터를 추가했다. Whisper verbose_json 원본 구간을 사용하며, 주장 ID는 서버가 생성한다. 인용문은 연속·정순·중복 없는 전사 구간에 존재해야 하고 구조화 속성은 인용문에 있어야 한다. 숫자는 토큰 경계를 검사해 50을 5로 바꾸는 오류를 거부한다. Brave 스니펫은 근거로 쓰지 않고 최대 3개 후보 중 원문을 확보한 첫 문서 1개/주장을 검증한다. 추출 입력은 32,000 bytes, 출력 2,048 tokens, 원문 구조화 발췌는 18,000 bytes로 제한하며 전체 원문을 Validator에 보존한다. 실패·미확인 호출의 예약 비용은 유지한다. SDK 단가 환산은 청구서가 아니다.

## 2026-10-17 후속 구현 상태

apps/api/src/storage.ts의 mediaDirectory/incomingFile은 UUID 자식 경로만 생성한다. readableMedia는 정해진 source 파일명·저장 절대 경로 일치·realpath·정규 파일 여부를 검사한다. app.ts와 cleanup.ts가 이 경계를 사용한다. 검사 후 파일 열기 사이 같은 UID 쓰기 경쟁은 잔여 한계다.

검증 근거: [10 최신 기록](10_파일_점검_현황.md#27-미디어-경로-보호와-전체-가이드-갱신-2026-10-17), [보안 지적 수동 검토](reports/2026-10-17-security-review.md).

## 파일 descriptor 보호 후속 (2026-10-17)

storage.ts의 readableMedia를 openMedia(root,id,storedPath): Promise<FileHandle>로 교체했다. 구성된 root를 연 다음 UUID 디렉터리와 source 파일을 descriptor 기준 /proc/self/fd 경로 및 O_NOFOLLOW로 연다. 디렉터리는 즉시 닫고, 정규 source 파일 descriptor는 Express callback 이후 finally에서 닫는다. O_NONBLOCK으로 FIFO 열기 대기를 막고 stat으로 정규 파일만 허용한다. 이미 연 파일/디렉터리 이름을 바꿔도 원래 연 파일을 읽는 회귀 2건을 확인했다.

## 응답 중단 정리 검증 (2026-10-17)

실제 loopback HTTP 서버에서 활성 미디어 응답을 중단한 뒤 /proc/self/fd의 해당 source descriptor가 모두 닫히는지 확인한다. 정상 전체 응답·거부된 Range 응답도 검사한다. FileHandle GC 경고를 감시해 자동 정리가 누락을 가리지 못하게 했고, 명시적 close를 제거한 변이에서 실패함을 확인했다.
