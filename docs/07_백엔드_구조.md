## 파일 descriptor 보호 후속 (2026-10-17)

storage.ts의 readableMedia를 openMedia(root,id,storedPath): Promise<FileHandle>로 교체했다. 구성된 root를 연 다음 UUID 디렉터리와 source 파일을 descriptor 기준 /proc/self/fd 경로 및 O_NOFOLLOW로 연다. 디렉터리는 즉시 닫고, 정규 source 파일 descriptor는 Express callback 이후 finally에서 닫는다. O_NONBLOCK으로 FIFO 열기 대기를 막고 stat으로 정규 파일만 허용한다. 이미 연 파일/디렉터리 이름을 바꿔도 원래 연 파일을 읽는 회귀 2건을 확인했다.

검증: [10 §29](10_파일_점검_현황.md#29-파일-descriptor-보호-후속-2026-10-17).

## 응답 중단 정리 검증 (2026-10-17)

실제 loopback HTTP 서버에서 활성 미디어 응답을 중단한 뒤 /proc/self/fd의 해당 source descriptor가 모두 닫히는지 확인한다. 정상 전체 응답·거부된 Range 응답도 검사한다. FileHandle GC 경고를 감시해 자동 정리가 누락을 가리지 못하게 했고, 명시적 close를 제거한 변이에서 실패함을 확인했다.

검증 근거: [10 §30](10_파일_점검_현황.md#30-응답-중단-파일-정리와-range-오류-검증-2026-10-17).

## TASK-023 수집·구조화·검증 책임 계약 (2026-10-18)

[02의 일반 원문 인수 조건](02_기능_설계.md#task-023-일반-원문-계약-1차-고정-2026-10-18)을 기준으로 다음 책임을 분리한다. 현재 구현 완료가 아닌 후속 구현 경계다.

4. publication date와 observation period·modified date를 별도 취급한다. 페이지에 기관명/날짜가 존재해도 발행자/발행일 확정이 아니다. 메타태그/JSON-LD도 페이지의 자체 주장으로 취급하고 본문과 충돌하면 유보한다.
5. 원출처/재인용 관계를 확인하기 전 lineage=host는 중복 힌트다. 독립 출처 수·근거 강도로 승격하지 않는다. 관련 오류/미지원/불충분을 성공 반박으로 합치지 않는다.

EvidenceDocument/EvidenceCheck.sourceTrace와 API의 nullable 필드를 추가했다. 신규 규칙 audio-numeric-canonical-v3는 trace 불일치·반복 인용·불완전 구조·발행정보 충돌·출처 진위 미확인을 유보한다. 기존 숫자 문법과 legacy 결과는 유지하며 일반 문서 긍정 판정은 추가하지 않았다. 저장 권한 확인 전 원문 사본/검색 응답의 영속 보관을 새로 추가하지 않는다.

## TASK-023 원문 추적 구현 범위

source_document.py의 static-text-v1은 정적 HTML/XHTML/UTF-8(ASCII 포함) plain만 처리한다. plain의 HTML 유사 문자를 보존한다. 문단·표 머리글/셀·caption·aside 주석·제목의 정규화 위치를 유지하며 구조 블록2048개가 넘으면 전문은 유지하되 structureComplete=false다. 과도한 DOM 깊이256/노드100000은 DOCUMENT_STRUCTURE_LIMIT로 후보를 거부한다. 단일 순회로 조상 반복 탐색을 피한다.

발행정보는 meta/time attribute의 값과 서버 생성 ordinal locator를 연결한다. 후보32개/필드·값500자 한도를 넘으면 invalid로 유보하며 모델의 publisher/date 후보가 서버 관측값을 덮어쓰지 못한다. JSON-LD·본문 기관 신원·재인용 계보/독립성·문단/표의 의미와 일반 문서 확정 판정은 후속이다. 새 trace는 SOURCE_AUTHENTICITY_UNVERIFIED로 확정 근거에서 제외한다. raw/text hash는 수집본 일치 추적이며 발행자 인증 서명이 아니다.

## 출처 등록 대조·관계 모듈 (2026-10-19)

source_review.py가 versioned source_registry.json을 코드 데이터로 로드한다. 실제 목록은 source-registry-v1-empty/entries=[]다. 등록에는 publisherId/name/exact hosts/reviewedAt/reviewReference가 필요하며 포트가 붙은 host·중복 host/ID·빈 검토 근거를 거부한다. 실제 등록 전 기관의 독점 관리 호스트/대표 이름/검토 근거를 확인하고 버전을 올린다. 공유 플랫폼 루트/임의 하위도메인을 기관 전체로 승인하지 않는다.

등록 대조는 새 네트워크 검증이 아니라 서버가 수집한 HTTPS 최종 URL/원문 trace와 trusted 목록·관측 publisher의 비교다. 원문 신원/기사 진위·사실성·독립성 인증은 아니다. sourceReview는 검토 버전/등록 버전과 가능 그룹/신호만 전달한다. source_document.normalize_source_url은 DNS/네트워크 요청 없이 링크를 안전하게 해석하고 query/path를 임의 제거하지 않는다. 최대5개 후보/링크32개 한도 안에서 관계를 비교한다. 무효 URL 후보의 그룹ID도 서로 구분한다. Protocol로 결과 모델과의 runtime/타입 의존 순환을 피한다.


## TASK-023 표 인용 맥락 유보 보완 (2026-10-19)

현재 규칙은 `audio-numeric-canonical-v4`다. 인용 범위가 table_cell/table_header와 겹치면 `TABLE_CONTEXT_UNVERIFIED`를 기록한다. 셀/헤더의 숫자만으로 행·열·분모·단위·주석의 의미를 확정하지 않는다. 관계없는 표가 있다는 이유만으로 문단 인용에 이 사유를 붙이지 않는다. 기존 전체 원문 맥락/출처 인증 유보는 유지하며 일반 표 의미 해석·실자료 정확도 검증은 미완료다. 신규 API 필드/DB 변경 없이 기존 reasons로 전달한다.


## API 브라우저 보호 보완 (2026-10-19)

모든 API 응답은 Origin 검사 이전 공통 미들웨어에서 X-Frame-Options DENY, Content-Security-Policy(default-src/frame-ancestors/base-uri/form-action none), Cross-Origin-Resource-Policy same-origin, Referrer-Policy no-referrer를 설정한다. 기존 nosniff/no-store와 비허용 Origin403을 유지한다. JSON 필드/상태 계약은 바꾸지 않는다. 정상206 미디어·400/403/404 오류 경계를 검증했고 기존 브라우저 재생/업로드/삭제 회귀를 유지한다. 인증·개별 데이터 소유권 대체가 아니며 운영 공개는 미완료다.


## TASK-027 읽기 전용 관리자 화면 (2026-10-19)

새 admin.ts의 조회 Router를 API 공통 Origin·보안 헤더·오류 처리 경계 안에 연결했다. Secret은 옵션/환경에서 서버만 읽고 고정 길이 digest로 검사한다. 한 SQL문으로 상태·최근 작업·월 비용을 조회하며 오류는 허용 목록으로 제한한다. 클라이언트의 경로·버전·주장을 권한으로 신뢰하지 않는다. Compose는 새 토큰을 API에만 전달하며 Worker/web에는 주입하지 않는다.


## TASK-023 표 구조 연결 (2026-10-19)

source_document.py의 static-text-v3는 TableLocation과 블록별 nullable 연결을 추가한다. 표/행 상태를 DFS stack에 함께 전달하므로 조상 반복 탐색이나 행·열 격자 확장은 하지 않는다. 병합 값은 ASCII 1~4자리와 상한1000으로 제한한 뒤 정수화한다. MAX_NODES100000/MAX_DEPTH256/MAX_BLOCKS2048을 유지한다. sourceTrace 스키마만 확장했고 판정 규칙v4/검색/비용 제한은 변경하지 않았다.


## TASK-023 표 설명 후보 연결 (2026-10-19)

table_context.py의 build_table_context는 서버 원문·해시·유일 인용·표 위치를 대조해 한정된 후보를 만든다. SourceTrace/TableContext/Fragment 모델은 블록·표 참조와 완전성 제약을 검사한다. Validator는 들어온 맥락을 지우고 다시 계산한다. pipeline은 tableContextVersion을 서버 값으로 덮어쓰며 RULES는 같은 모듈을 실행하고 소스 SHA-256과 버전을 기록한다. parser static-text-v3와 숫자 규칙 audio-numeric-canonical-v4는 유지한다.


## 계정·추출·운영 모듈 (2026-10-19)

API auth.ts는 opaque session/scrypt/로그인 시도 제한, auth-config.ts는 공개 accounts/HTTPS origin 강제, upload-limits.ts는 advisory lock과 DB 예약 기반 총량·개수·동시 업로드 한도를 제공한다. 각 데이터 쿼리는 owner_id IS NOT DISTINCT FROM 세션 소유자를 사용하며 로컬 NULL 자료는 계정 접근에서 제외한다.

Worker visual.py는 private FFmpeg/Tesseract 파생물·시간/범위·부분 오류를 생성한다. multimodal.py는 제한된 수치 관측 비교만 수행하고 report.py는 주장 결과 집계만 한다. pipeline은 원본 sourcePath를 별도 사용하며 음성 어댑터와 외부 판정 규칙을 유지한다. Worker 이미지에는 FFmpeg/Tesseract/kor+eng를 포함한다.

운영 구성은 compose.production.yaml, nginx.production.conf와 production-init/preflight/recovery 도구다. 기존 compose.yaml은 명시적 local 전용이다. 운영 프록시는 loopback cloudflared→nginx→API의 신뢰 경계를 전제로 nginx가 X-Forwarded-For를 덮어쓰고 API가 정확히 한 프록시 hop을 신뢰한다. 공개 listener나 다른 프록시 경로로 변경하면 신뢰 구성을 다시 검증한다.


명시 헤더 관측은 table_references.py의 독립 table-reference-audit-v1, 대표 맥락은 table_context.py의 table-cue-audit-v1이다. static-text-v3의 정규화 텍스트·블록 파싱 버전은 유지하고 각 감사 버전과 새 모듈 SHA-256을 파이프라인/생산 RULES 실행에 서버 값으로 기록한다. LLM이 같은 버전 키를 반환해도 덮어쓴다. 새로운 관측은 validate_evidence/decide 규칙을 완화하지 않는다.


## TASK-028 서버 개선 범위 (계획)

scrypt·해시 세션·Secure/HttpOnly 쿠키·소유권 검사를 유지한다. 계정 변경/탈퇴에는 재인증, 요청 출처 확인, 제한된 비밀번호 해시 작업, 전체 세션 폐기와 작업/파일 삭제 경합 처리가 필요하다. 비용 기록을 계정 삭제와 무조건 함께 지우지 않는다. 구현 전 API/DB 정합성·외부 계정 접근 거부·실패 원자성 회귀를 정의한다.


## 관리자 계정·운영 화면 개선 — 확정 요구 (2026-10-19)

공개 가입 경로와 분리된 최초 관리자 생성 CLI, 비밀번호의 숨김 입력/해시 저장, 서버 측 역할 검사, 관리자 API 조회 범위/횟수 제한을 구현한다. 기존 토큰을 계정 생성 비밀번호로 사용하지 않는다. 계정 기반 접근으로 전환한 뒤 기존 Bearer 인증 우회 경로를 제거하고 토큰을 브라우저 저장소에 보관하지 않는다.
