## 1. 환경 구분

| 환경 | 목적 | 현재 상태 |
|---|---|---|
| 현재 클라우드 개발 환경 | 문서 작성과 개발 도구 사용 | devtools 설정 존재 |
| 제품 개발/테스트 환경 | 웹사이트 실행과 제품 테스트 | 미구성 |
| 스테이징/운영 | 사용자 대상 배포 | 배포처·도메인·절차 미결정 |

## 2. 현재 개발 도구 절차

작업 디렉터리: `/workspace/Fact-checking-website`.

```bash
bash devtools/install.sh
source devtools/activate.sh
# 아래는 선택 AI 게이트웨이가 필요한 작업에서 실행
python3 devtools/start-services.py
```

설치 도구와 upstream 캐시는 `/workspace/.devtools`에 둔다. `install.sh`는 제품 파일을 만들지 않는다. 자세한 도구 버전과 제한은 [개발 도구 안내](../devtools/README.ko.md)를 참조한다.

| ID | 절차 | 준비 조건 | 확인 기준 |
|---|---|---|---|
| OPS-001 | 도구 설치/갱신 | Python 3.12+, uv, Node 24, npm, Git 및 패키지 접근 | install 종료코드 0, Python 의존성 호환성 검사 |
| OPS-002 | 선택 게이트웨이 시작 | OPS-001 완료, 포트 20128/8787 사용 가능 | OmniRoute 상태 정상, Headroom ready=true |

설정 스크립트 확인 기준이며 이번 문서 작업에서 설치/서비스 검사를 다시 실행한 것은 아니다. 이전 실행 결과는 `devtools/README.ko.md`의 기록이다. 실제 모델 추론은 그때도 미검증이다.

## 3. 설정·비밀·네트워크

- MCP는 `.codex/config.toml`에 있다. 현재 경로는 이 클라우드용 절대 경로다.
- 스킬 링크와 캐시가 다른 머신으로 자동 복제된다고 가정하지 않는다. 새 환경에서 설치·발견을 재검증한다.
- 제공자 인증은 사용할 모델을 결정한 뒤 환경 설정에서 추가한다. 값은 Git에 저장하지 않는다.
- 실제 필요한 외부 도메인과 용도를 기록하고 기존 네트워크 허용 정책을 보존한다.
- 프로세스는 환경 복원 후 재시작해야 한다. 정상 서비스가 이미 있으면 시작 도우미가 재사용한다.

## 4. 제품 배포 절차 작성 양식

채택 후 아래 항목을 구체적인 명령·권한·담당자·기대 결과로 채운다.

1. 런타임·리소스·빌드 대상·환경 변수 이름 및 주입 방법.
2. 정적 검사·테스트·빌드와 결과물 식별자.
3. DB 마이그레이션·백업·기존 버전 호환성.
4. 배포 순서·제품 readiness·대표 기능 smoke test.
5. 지표·로그·경보·호출 비용·운영 담당자.
6. 장애 판별·롤백 트리거·코드 롤백·데이터 복구·복구 후 검증.

삭제·복구·배포가 필요한 권한은 해당 실행 시점의 사용자 지시에 따른다. 문서 존재만으로 운영 배포를 승인한 것으로 보지 않는다.

## 5. 저장과 게시 상태

개발 환경 `install_script`/`start_skill` 초안은 이전 작업에서 저장되었다. 이는 환경 게시나 GitHub push의 증거가 아니다. 이 문서 세트와 참조 도구/설정은 2026-10-15 사용자 요청으로 GitHub main 반영 대상으로 준비했다. 반영 성공 여부는 푸시 후 원격 커밋 대조로 확인한다. 클라우드 환경 게시와 제품 배포는 별도이며 미실행이다.

## 7. 기획서 단계별 실행·평가 준비 기준

근거: [원문](../references/FactLens_AI_기획서_원문.md) 09·13·15~16절. 실행 기록은 아직 없으며 다음은 준비할 절차다.

| 단계 | 준비/구현 대상 | 원문 완료 기준 |
|---|---|---|
| 음성 PoC | MP4 업로드·추출·STT·주장·검색·비교·개별 판정 | 실제 사례의 주장/근거/판정을 일관된 구조로 생성 |
| 시각 PoC | 프레임·OCR·시각 분석·음성/자막 수치 비교·이미지 일치 탐색 | 사전 정답이 있는 자막 불일치/영상 재사용 사례 탐지 |
| 통합 PoC | 시간 정렬·근거 Validator·교차검증·규칙·유보/검토 | 판정 근거와 적용 규칙의 재현 가능한 기록 |
| 웹 MVP | UI·플레이어·진행·타임라인·URL 근거·보고서·이력 | 기능 통합·성능 평가·시연 근거; 세부 인수 기준은 02에서 정의 |

원문 12주 예시는 1주 요구/사례, 2주 설계, 3주 업로드/FFmpeg/STT, 4주 주장, 5주 검색, 6주 Validator, 7주 프레임/OCR, 8주 시각 맥락, 9주 교차검증, 10주 UI/보고서, 11주 비교 평가, 12주 개선/발표다. 팀·예산·시작일 미정이므로 실제 일정으로 확정하지 않는다.

### 평가 실행 기록 요구 (TASK-014)

- A=전사/자막 텍스트 LLM, B=A+검색, C=검색/원문 검증/시각/교차검증/규칙 전체. 가능한 한 같은 평가 자료와 주장 목록을 쓴다.
- 목표 90~120개 영상/구간: 사실·허위 수치·자막 불일치·화면 맥락 왜곡·근거 부족을 포함하고 직접 확인한 정답 근거를 주석한다. 확보 수는 별도로 기록한다.
- 개발/평가 분할, 원본 계열 중복 방지, 라벨 기준, K와 분모, 목표치, 모델/검색 조건은 실행 전에 고정한다.
- Claim Recall, Evidence Precision@K, Evidence Validity, Verdict Macro-F1, Cross-modal F1, False Verdict Rate, Abstention Rate와 처리 시간/비용을 기록한다. 지표별 정의와 평가 스크립트는 아직 없다.
- 실행 ID·입력/정답 버전·설정/규칙 버전·원시 출력·오류·사용량·환경·실행 명령을 남겨 비교 가능하게 한다. 결과 저장 경로/도구는 프로토콜에서 정한다.
- 기대 개선이 없더라도 실제 결과를 보고한다. 유보율만으로 성능을 주장하지 않는다.

외부 호출 전 파일/시간/프레임/주장/동시성/재시도/비용 상한과 데이터 전송 범위를 정한다. 검색 캐싱·중복 제거는 비용 개선 제안이며 개인정보/출처 최신성·삭제와 함께 검토한다. 프레임 공개 URL은 별도 동의와 공개 가능 여부 확인 없이 만들지 않는다.
