### 평가 실행 기록 요구 (TASK-014)

- A=전사/자막 텍스트 LLM, B=A+검색, C=검색/원문 검증/시각/교차검증/규칙 전체. 가능한 한 같은 평가 자료와 주장 목록을 쓴다.

## 탈퇴·복구 운영 보호

탈퇴는 물리 계정 행 삭제 대신 접근 불가/개인 필드 제거된 tombstone을 남겨 비용 연결과 legacy 소유권 분리를 유지한다. 진행 중 작업/업로드는 완료 후 재시도하며 대기 작업은 폐기한다. 파일 삭제 실패는202로 안내하고 cleanup의 재시도 대상이 된다. 삭제 오류 경보·재시도 기한·비용 원장 법적 보관 기간은 추가 운영 정책이 필요하다.

복구 도구는 복원한 모든 사용자 이름을 restored_UUID로 치환하고 암호를무효화·deleted_at을설정한다. 백업 이후 탈퇴/암호변경 여부를 알 수 없으므로 옛 로그인 정보를 그대로 활성화하지 않는다. 복구 DB는 새 격리 대상에서만 생성하며 운영 전환 전 별도 새 관리자를 생성/본인 확인 계정 복구 절차를 검토해야 한다. 현재 자동 사용자 복구 기능은 없다. 파일/보고서 미복구·비용 재조정/AI중지 원칙은 유지한다.


## 관리자 생성 컨테이너 검증과 서버 반영 순서

10 §60에서 별도 factlens-admincheck 운영 Compose의 API/DB/Redis/미디어 볼륨으로 실제 대화형 create-admin.py를 검증했다. 비밀번호는 메모리에서 생성해 PTY 숨김 입력했고 출력하지 않았다. 정상 생성/동일 이름 재생성 거부·Secure 세션·overview v2와 필터·일반 회원403·로그아웃 후401을 확인했다. 테스트 프로젝트만 down --volumes로 정리했으며 기존 개발 DB/Redis와 실제 AWS는 보존했다.

최초 운영 반영 절차(배포/백업/전환 완료, 관리자 전체 회귀는 후속):

1. 서버의 work가 게시된 최신 구현 커밋을 받았는지 확인한다. .env.production은 유지하고 내용을 채팅/로그에 출력하지 않는다.
2. 진행 중 작업/업로드가 없는 유지보수 구간을 잡고 private DB 백업을 새 디렉터리에 저장한다. 현재 복구는 미디어 미복구/계정 비활성화인 제한 복구임을 확인한다.
3. 운영 Compose로 이미지를 빌드하고 up -d 한다. API 시작 시004/005 마이그레이션이 적용된다. Bearer 토큰은 더 이상 로그인 수단이 아니다.
4. 대화형 SSH에서 python3 devtools/create-admin.py 실행, 새 관리자 이름/숨김 암호/확인 입력. 기존 회원을 덮어쓰지 않는다.
5. 공개 HTTPS에서 관리자 로그인/일반 회원 접근 거부·검색/페이지·로그아웃, 회원 가입/변경/탈퇴·업로드/삭제를 검증한다. AI는 비활성화 유지.
6. 검증 후 기존 관리자 토큰 Secret을 폐기한다. 실패 시 구버전 인증만 급히 되살리지 말고 유지보수 상태에서 복구/권한·마이그레이션 상태를 확인한다. 공개 경로·다른 기존 서비스는 변경하지 않는다.

현재 전용 고정 지문 SSH와 Aside 브라우저 연결을 확인했다. 최초 배포 단계는10 §67에서 완료했으므로 반복하지 않는다.10 §68의 공개 계정 검증과 별도로 업로드/삭제·관리자 로그인/검색/페이지 회귀가 남는다. 관리자 암호를 채팅으로 요청하지 않는다.


## 사용자 SSH에서 실행할 배포 단계

현재 에이전트에는 원격 SSH/열린 브라우저 터미널 제어 도구가 없다. 아래 명령은 새 Lightsail factlens-ai의 ubuntu SSH에서 실행한다. 첫 단계는 기존 서비스를 중지하지 않는다.

### 1. 소스 갱신·사전 점검·빌드

```bash
cd ~/factlens && git pull --ff-only origin work
sg docker -c 'python3 devtools/production-preflight.py'
sg docker -c 'docker compose --env-file .env.production -f compose.production.yaml build'
```

각 명령이 성공한 뒤 다음 명령으로 진행한다. init은 다시 실행하지 않는다. .env.production의 비밀값은 그대로 보존하며 출력하지 않는다. 빌드 성공 결과 확인 전 서비스 전환을 실행하지 않는다.

### 2. 짧은 유지보수·private 백업·전환

작업/업로드가 진행 중이지 않은 시점에 실행한다. 이 단계는 웹 접속을 잠시 중단한다. 백업 실패 시 다음 up을 실행하지 않고 원인부터 확인한다. 운영 백업 루트는 처음 만들 때0700이며 기존 디렉터리의 안전성을 별도로 확인한다.

```bash
mkdir -p -m 700 ~/factlens-backups
sg docker -c 'docker compose --env-file .env.production -f compose.production.yaml stop web api worker'
sg docker -c 'python3 devtools/recovery.py backup --container factlens-postgres-1 --database factlens --directory "$HOME/factlens-backups/pre-account-$(date -u +%Y%m%dT%H%M%SZ)"'
sg docker -c 'docker compose --env-file .env.production -f compose.production.yaml up -d --wait'
```

이 백업은 DB만 포함하고 복구 시 계정 비활성화/미디어 미복구다. 전체 무손실 롤백으로 간주하지 않는다. 컨테이너/볼륨 삭제나 down --volumes는 운영에서 실행하지 않는다.

### 3. 관리자 생성·상태 확인

```bash
sg docker -c 'python3 devtools/create-admin.py'
sg docker -c 'docker compose --env-file .env.production -f compose.production.yaml ps'
curl --fail --show-error --max-time 20 https://factlens.pigs0516.com/api/health
```

관리자 이름과 비밀번호는 명령 실행 후 대화형 입력한다. 비밀번호는 표시되지 않으며 채팅에 보내지 않는다. /admin에서 생성 계정으로 로그인하고 일반 회원 접근 거부·로그아웃도 확인한다. 기존 토큰을 입력하는 구화면이 보이면 새로고침 후 이미지/캐시 상태를 확인한다. AI 활성화는 이 배포의 범위가 아니다.
